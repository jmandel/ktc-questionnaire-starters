The distinction

USCDI exchange vs. a necessary questionnaire

Most "intake clipboard" content already lives in the chart as structured US Core data. Re-asking for it is the failure mode. Questionnaire earns its place only when the capture event itself matters.

Don't ask Retrieve from USCDI / US Core

If the chart already knows it, prefill or reconcile — never make the patient retype it.

DemographicsMedications AllergiesProblems LabsVitals ProceduresEncounters CoverageCare team NotesHealth-status observations

Do ask Capture as a Questionnaire

Use a Questionnaire when the system must know, with provenance:

  • exactly what question was asked, and the exact answer set;
  • the score or interpretation method;
  • when the patient answered — and whether it's fresh enough for this visit;
  • whether the response should trigger a workflow (referral, safety follow-up, alert).
Implementation rule

Five questions to ask before you ask the patient

Apply this test to every candidate field. It keeps a questionnaire library from quietly becoming a digital clipboard.

1

Can this be retrieved as USCDI / US Core data?

Patient, Medication, AllergyIntolerance, Condition, Observation, Procedure, Encounter, Coverage…

If yes → retrieve or prefill instead of asking
2

Is the existing data fresh enough for this workflow?

Reuse it when it is. Ask the patient only when it's missing, stale, or due.

If no → ask, using "due / missing / stale" logic
3

Does exact wording, answer set, or scoring matter?

Standardized instruments depend on phrasing and a defined response scale.

If yes → use Questionnaire + QuestionnaireResponse
4

Does the answer need to be searchable or trendable?

Scores feed dashboards, quality measures, CDS, and longitudinal display.

If yes → extract a LOINC-coded Observation
5

Does the answer require action?

A result that demands response can't just disappear into a data store.

If yes → create local workflow: Task, alert, referral, safety follow-up

The FHIR pattern

      
Three resources, one provenance chain

      
In FHIR R4 the Questionnaire carries the item codes; the QuestionnaireResponse
        records answers by linkId; an extracted Observation makes the score searchable.

    

    

      

        
Questionnaire

        
The form definition

        
Canonical URL, LOINC panel code, item codes, answer options with ordinal scores, version, copyright.

      

      
→

      

        
QuestionnaireResponse

        
The patient's answers

        
Answers by linkId, author / source, authored timestamp, link back to the Questionnaire. The raw provenance record.

      

      
→

      

        
Observation

        
The searchable score

        
category=survey, LOINC score code, valueQuantity in {score}, derivedFrom the response.

Governance guardrails

      
Keep it a questionnaire library, not a clipboard

    

    

      
🚫
No re-asking USCDI facts

        
If it's available as US Core data, retrieve it first. Never default to re-collection.

      
⏱️
Due / missing / stale logic

        
Ask an instrument only when clinically due, missing, stale, or needed for the current episode.

      
🧾
Preserve the raw response

        
Keep the QuestionnaireResponse: exact form, wording, answer, respondent, and timestamp.

      
🔎
Extract only useful Observations

        
At minimum the score. Extract per-item Observations only when search / CDS / reporting needs them.

      
©️
Represent licensing explicitly

        
Set copyright, publisher, version, source, and "do not modify" notes.

      
🚨
Escalation is local but required

        
PHQ-9 item 9, severe dyspnea / pain, high alcohol risk must route somewhere — not vanish into storage.
